# Каталог организаций и структурированные отзывы

Документ для Codex. **Текущий этап — статическая веб-версия на GitHub Pages, без сервера.**

## Источники названий

В `data/organizations.js` находятся **50 реальных названий** компаний или групп предприятий, связанных с нефтегазом, промышленным и инфраструктурным строительством, вахтовой работой и спецтехникой.

Для исходных названий использованы:
- [Официальная структура группы «Газстройпром»](https://gsprom.ru/company/structure/).
- [Рейтинг нефтегазостроительных компаний ТЭК-рейтинг](https://www.tek-r.ru/rating/7-%D0%A0%D0%B5%D0%B9%D1%82%D0%B8%D0%BD%D0%B3%20%D0%BD%D0%B5%D1%84%D1%82%D0%B5%D0%B3%D0%B0%D0%B7%D0%BE%D1%81%D1%82%D1%80%D0%BE%D0%B8%D1%82%D0%B5%D0%BB%D1%8C%D0%BD%D1%8B%D1%85%20%D0%BA%D0%BE%D0%BC%D0%BF%D0%B0%D0%BD%D0%B8%D0%B9/).
- [Вакансии группы Газстройпром](https://orenburg.hh.ru/employer/3881744), [Ленгазспецстрой — машинист экскаватора](https://hh.ru/vacancies/mashinist_ekskavatora/vakhtoviy_metod), [СибПромСтрой](https://www.sps70.ru/jobs/), [СибТрансСтрой](https://sts-38.ru/), [Сибдорстрой](https://rtvahta.ru/kompanii/ooo-sibdorstroy/), [СибТрансАвто](https://dreamjob.ru/employers/114946/vakansii/136662593).

Это **справочник названий**, а не подтверждение, что каждая компания прямо сейчас имеет открытые вакансии машиниста экскаватора или бульдозера. Исходный URL указан для каждой записи. Для идентификаторов использованы внутренние `org-...`, а не выдуманные ИНН/ОГРН.

Поиск учитывает сокращения и варианты написания. Запросы «СИП-Промстрой» и «СИП-Трансстрой» пока являются пользовательскими вариантами ввода для **СибПромСтрой** и **СибТрансСтрой**. Пока не подтверждено, что написания «СИП...» являются официальными названиями этих организаций; перед публикацией настоящего юридического справочника такую нормализацию необходимо проверить.

**Очень важно:** десять примеров отзывов, истории работы друзей и их оценки — полностью вымышленные. Они нужны для тестирования интерфейса и НЕ являются свидетельствами о реальных условиях в перечисленных организациях. В карточке примерные отзывы имеют пометку «пример». Иллюстрации `assets/review-*.svg` не являются фотографиями реальных предприятий.

## Организация и рабочий объект — разные сущности

Будущая серверная модель:
```text
organizations(id UUID, legal_name, trade_name, inn nullable, ogrn nullable, source, verified_at)
organization_aliases(organization_id, alias)
worksites(id UUID, organization_id, name, region, type)
employment_history(id UUID, account_id, organization_id, worksite_id nullable, start, end, visibility)
organization_reviews(id UUID, organization_id, worksite_id nullable, author_account_id, scope, anonymous, created_at, overall)
review_sections(id UUID, review_id, criterion_code, rating_1_to_5, comment, media_id nullable)
review_viewers(review_id, account_id)   # для видимости избранным друзьям
media(id UUID, owner_account_id, storage_key, status, created_at)
```
Под одним `review_id` хранятся все пункты одного отзыва. Отзыв привязан к организации, а при наличии объекта — ещё и к нему. Публичные рейтинги учитывают **только общедоступные отзывы**; скрытые рейтинги никогда нельзя выдавать через агрегаты.

## Текущий UI и структура данных

`data/organizations.js` — каталог из 50 строк (`id`, `name`, `industry`, `aliases`, `source`), доступен браузеру через `window.MV_ORGANIZATIONS`.

`data/organizations-ui.js` — чистая поисковая логика и функции, привязанные к UI: `window.MV_ORG`. Она предоставляет `byId`, `byName`, `matches`, `enrichState`, `detailPage`, `catalogPage`, `reviewEditor`, `saveReview`, `publicRating`, `reviewsForFriend`.

`app.js` — маршрутизация экранов `organizations` и `organizationDetail`, кнопки перехода из списка друзей, из анкеты, из главной и раздела «Ещё», диалоги редактирования/фотографий и настройка видимости.

Для каждого отзыва предусмотрены семь критериев: зарплата, бытовые условия, питание, руководство, график вахты, техника и безопасность, проезд и логистика. Каждый критерий хранит **одну оценку, комментарий и не больше одной фотографии**. Общий комментарий, объект, анонимный показ имени и доступ `all/friends/selected/self` — поля записи отзыва.

Выбранная организация в профиле хранится как `state.org.organizationId`; для друзей исторические места работы — `state.accounts[accountId].workHistory[].organizationId`. **Не хранить и не показывать историю без проверки настроек приватности на будущем сервере**: текущие связи относятся исключительно к вымышленным друзьям.

Фото пользователя принимается из браузера в JPG/PNG/WebP (до 6 МБ исходный файл), уменьшается с помощью canvas до максимальной стороны 1000 пикселей, затем сжимается в JPEG и сохраняется в памяти браузера вместе с отзывом. Размер каждой сжатой фотографии ограничен (около 170 КБ). На GitHub Pages файлы других пользователей не публикуются, и серверной синхронизации пока нет. Перед переносом в Django необходимо внедрить серверную обработку файлов, защиту данных, модерацию, EXIF-очистку, сканирование и отдельное объектное хранилище.

## Ограничения и миграция

- Старые сохранённые аккаунты, друзья, переписка, финансы и заметки остаются; расширение добавляет ещё 12 вымышленных друзей (всего 16) и десять примерных отзывов **однократно**.
- Примерные новые профили и отзывы не являются реальными пользовательскими записями. Перед запуском сервера их не следует импортировать как реальные отзывы или реальные трудовые отношения.
- `migrateSocial()` сохраняет `workHistory` и `currentOrganizationId` внутри каталога аккаунтов.
- `organizationReviews` является нормализованным общим источником для анкет и страниц компаний, а не отдельными копиями отзывов.
- В разработке пока не нужен Django/PostgreSQL и отдельный VPS. Но сами идентификаторы и границы сущностей готовы к будущему API.
- Поиск справочника в клиенте выполняется локально по 50 строкам; при большом каталоге должен быть заменён на индексированный API-поиск с ограничением выдачи.
- Хранение больших медиа в `localStorage` — только временный вариант для проверки UX и не подходит для публичной социальной сети.
- Автору должен быть доступен редактор отзыва; полноценная проверка роли/дружбы/списка разрешённых пользователей будет выполняться **на сервере** до выдачи данных.
- В пользовательском интерфейсе не показывать подробные технические сообщения; подробности оставлять здесь.
