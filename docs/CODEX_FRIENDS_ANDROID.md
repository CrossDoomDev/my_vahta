# Моя вахта — друзья, контакты и заявки (памятка для Codex)

**Статус, 25 октября 2026:** интерфейс и локальные учебные сценарии реализованы в `app.js` + `friends.css`. **Настоящая регистрация, поиск пользователей, заявки между устройствами и push-уведомления пока отсутствуют.** Нельзя выдавать демоданные за реальных пользователей.

## Целевая платформа

Основной продукт — Android-приложение. Веб-версия остаётся средой прототипирования интерфейса. Использовать привычный мобильный паттерн «Друзья → Найти друзей → Отправить заявку → Принять/Отклонить», отдельные списки входящих и отправленных заявок, счётчики на вкладке и в уведомлениях, возможное приглашение ссылкой или QR-кодом.

## Уже реализовано в прототипе

- `state.accounts` содержит словарь профилей, `state.friends` ссылается на `accountId`, `state.friendRequests` хранит `{id,accountId,direction,status,createdAt,demo}`.
- Миграция локальных данных `migrateSocial` поддерживает старые версии без `friendRequests`.
- `friendDiscoveryPage()`, `friendsPage()`, `friendRequestItem()`, `notificationsPage()` — интерфейсы; `demoIncomingRequest()`, `sendDemoFriendRequest()`, `finishFriendRequest()` — **локальные тестовые действия**, не сетевые запросы.
- Тестовые профили `demo-*` и старые `f1`—`f4` помечаются как демо; создавать произвольных «друзей» ручным вводом имени больше нельзя.
- Существующие ранее локально записанные друзья не удаляются при обновлении.
- Уведомления с типами `friend_request`/`friend_accepted` хранят `requestId`/`accountId`, выводят действия «Принять»/«Отклонить». Счётчик ожидающих запросов выводится у «Друзья».
- В `pickFriendContact()` предусмотрена точка подключения `window.MVNativeContacts.pickSingle()`. В некоторых мобильных браузерах есть fallback `navigator.contacts.select(['name','tel'], {multiple:false})`; выбор происходит по запросу пользователя. **Телефоны не записываются в локальное хранилище и не отсылаются никуда.**
- `shareFriendInvite()` сейчас делится только ссылкой на **прототип** (не персональной заявкой и не установочным APK).

## Для следующего этапа — реальная Android + серверная интеграция

1. **Аккаунты.** Создать серверную регистрацию/вход, постоянный `userId` (не имя и не номер телефона), безопасную сессию, подтверждение владения телефоном через одноразовый код (по желанию), настройку «Можно найти меня по номеру». Не создавать реальные профили только по имени, введённому другим человеком.
2. **Поиск по ID и имени.** API поиска только среди существующих и разрешивших поиск аккаунтов, с пагинацией, ограничениями частоты и блокировками. Никакой переборной выдачи номера, наличия аккаунта по произвольному телефону, контактов или персональных данных.
3. **Контакты Android.** Использовать системный выбор **конкретных контактов**, не запрашивать без крайней необходимости полную адресную книгу. Для Android 17 (API 37) доступен `ContactsPickerSessionContract.ACTION_PICK_CONTACTS`. Для прежних версий изучить `ACTION_PICK` / `ContactsContract.CommonDataKinds.Phone.CONTENT_TYPE` или эквивалент через Activity Result API с выбором конкретного номера. Проверить реальные устройства, доступные API и ограничения версий Android. Результат — в Android bridge -> JS / нативный UI, минимальные данные, без автоматической выгрузки адресной книги.
4. **Поиск по номеру.** Номер нормализуется (E.164) на доверенной стороне; матчинг разрешён **только при явном согласии владельца номера быть найденным**. Не считать простой хеш номера защитой от восстановления — номера перебираемы. Серверное сопоставление должно быть защищено от enumeration, спама и массового экспорта; ограничивать запросы и учитывать требования законодательства о персональных данных.
5. **Заявки.** Серверная сущность `friend_request {id, senderUserId, recipientUserId, status, createdAt, respondedAt}`. Только отправитель может отменить; только адресат — принять/отклонить. Проверять авторизацию и идемпотентность, исключить заявки себе, дубль-заявки и гонки; блокировки и настройки приватности учитывать на сервере. На принятии атомарно создать дружбу и событие уведомления. Никогда не принимать решения на основании локального `state.friendRequests`.
6. **Уведомления.** API inbox / unread-count; push для новых запросов и принятий (канал/доставка выбираются для фактического Android-дистрибутива), повторная синхронизация при запуске и возвращении приложения в foreground. Кнопки принятия из уведомления обязаны выполнять авторизованный серверный запрос.
7. **Приглашения.** Персональная invite/deep-link и QR-код, проверяемый сервером; при отсутствии приложения — установка из поддерживаемого магазина. Не считать нынешнюю ссылку на веб-прототип работающей дружеской заявкой.
8. **Миграция прототипа.** Не переносить `demo-*`, `f1`—`f4`, тестовые заявки и демонстрационные чаты в список подтверждённых людей. Отделить/очистить демоданные после включения backend; не удалять реальные пользовательские заметки, выплаты и графики вахт.
9. **Приватность и модерация.** Согласия, политика обработки данных, защита от нежелательных заявок, возможность пожаловаться, заблокировать, удалить контакт и отозвать согласие, удалить аккаунт/данные. Настройка обнаружения аккаунта должна быть только через «Ещё → Конфиденциальность».
10. **Тестирование.** Минимум два независимых аккаунта/устройства: отправка → push/входящая → принять/отклонить → список друзей на обоих устройствах; отмена, повторная отправка, гонка, блокировка, скрытый номер, отсутствие сети, дубли, восстановление сессии, Android без доступа к контактам.

Источники для Codex:
- MDN Contact Picker API: https://developer.mozilla.org/en-US/docs/Web/API/Contact_Picker_API
- Android 17 Contact Picker: https://developer.android.com/about/versions/17/features/contact-picker
- Android common intents (select phone): https://developer.android.com/guide/components/intents-common

**Важная граница доверия:** пока нет аккаунтов и сервера, интерфейс допускает только локальные **демонстрационные** заявки; нельзя сообщать пользователю, что реальная заявка была отправлена или получена.
