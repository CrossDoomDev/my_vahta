# Моя вахта — API v1 (локальный Django)

Базовый адрес: `http://127.0.0.1:8000/api/v1/`. Токен в заголовке `Authorization: Token <ключ>` после регистрации или входа. Доступ к личным данным — только владельцу. Выдавать API наружу без TLS **нельзя**.

## Авторизация и пользователь

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | health/ | Проверка Django + PostgreSQL |
| POST | auth/register/ | Регистрация: username, password, display_name |
| POST | auth/login/ | Вход: username, password; возвращает токен |
| POST | auth/logout/ | Отозвать токен |
| GET/PATCH | me/ | Мой профиль: display_name, profession, discoverable |
| GET/PATCH | me/privacy/ | Доступ к статусу, календарю, организации, финансам |
| GET/PATCH | me/notification-preferences/ | Персональные категории и сроки уведомлений |
| POST | me/presence/ | Отметить активность аккаунта онлайн (требует авторизации) |

Телефонный номер и синхронизация адресной книги **не внедрены**. Поиск по ID/имени показывает только `discoverable=true` и требует входа.

## Календарь, выплаты, заметки

| Метод | Маршрут | Назначение |
|---|---|---|
| GET/PUT | shift/ | Единственный серверный график `{start,end,vacation}` |
| GET | shift/summary/ | Получено за всю вахту, количество выплат, даты |
| GET/POST | payments/ | Только свои выплаты |
| GET/PATCH/DELETE | payments/{uuid}/ | Редактирование своей выплаты |
| GET/POST | notes/ | Только свои заметки |
| GET/PATCH/DELETE | notes/{uuid}/ | Редактирование своей заметки |
| GET/PUT | sync/ | Ручной пакет `{revision,shift,payments,notes}` |

Даты `YYYY-MM-DD`, включительно. Деньги — целое количество рублей, `type=advance|salary|bonus|other`. Финансы по умолчанию видны только владельцу. При изменении `shift`/платежей/заметок растёт `sync_revision`. `PUT sync` с неактуальной версией отвечает 409, не перезаписывает данные.

Запрос синхронизации является **полной заменой личных графика, выплат и заметок**. Нельзя вызывать его автоматически от имени пользователя до явного подтверждения импорта/экспорта. Демо-друзья, фальшивые чаты и вымышленные сведения об организациях в эту синхронизацию не включены.

## Настоящие друзья, заявки, сообщения

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | users/?q=... | Поиск согласившихся быть найденными пользователей; от 3 символов |
| GET | friends/ | Подтверждённые друзья; поля `is_online`, `work_status` с учётом видимости |
| DELETE | friends/{account_uuid}/ | Удалить из друзей |
| GET/POST | friend-requests/ | Список моих заявок / запрос с `recipient_id` |
| POST | friend-requests/{uuid}/accept/ | Принять заявку (только получатель) |
| POST | friend-requests/{uuid}/decline/ | Отклонить (получатель) |
| POST | friend-requests/{uuid}/cancel/ | Отменить (отправитель) |
| GET | notifications/ | Мои уведомления |
| POST | notifications/{uuid}/read/ | Отметить прочитанным |
| POST | notifications/read-all/ | Прочитать все |
| GET | notifications/unread-count/ | Счётчик непрочитанных |
| GET | messages/?peer={account_uuid} | Последние 100 сообщений с другом |
| POST | messages/ | Отправить другу `{recipient_id,text}` |

### Настройки уведомлений

`GET /api/v1/me/notification-preferences/` возвращает настройки авторизованного пользователя. 
`PATCH` принимает только перечисленные поля: `enabled`, `shift`, `payments`,
`holidays`, `friend_request`, `friend_accepted`, `message` (логические значения),
`shift_days` (0, 1, 3, 7 или 14) и `holiday_days` (0, 1, 3 или 7).
Например `{"message":false,"friend_request":true,"shift_days":7}`.
Неверный тип или неизвестное поле возвращает 400; настройки одного пользователя недоступны другому.

Переключатели влияют на **новые** серверные уведомления, счётчик и выдачу личного списка.
Отключённые уведомления не отменяют доставку сообщений и создание заявок; эти события доступны на экранах «Сообщения» и «Друзья». История ранее созданных уведомлений не удаляется.
Напоминания о вахте и профессиональных праздниках создаёт **веб-клиент при открытии сайта** и хранит локально. Ожидаемые даты выплат не хранятся — «Финансы» оповещают только о новых записях. Серверные системные push-сообщения и фоновые задания ещё не внедрены.

Поле `is_online` у подтверждённого друга становится `true`, если его авторизованный клиент подавал сигнал активности в течение последних трёх минут. Веб-клиент посылает сигнал примерно раз в минуту только при видимой странице; при выходе из аккаунта присутствие очищается. `work_status` показывает `shift`, `rest` или `vacation`, не раскрывая чужие даты. Когда `me/privacy/` ограничивает видимость `status` значением `self`, статусы и присутствие скрыты от друзей.

Данные профиля имеют серверный UUID, не имя и не номер телефона. Только получатель может принять заявку, а сообщение можно отправить только подтверждённому другу. Это HTTP API — push, WebSocket, загрузка контактов Android, блокировки и антиспам высокой нагрузки пока будущие задачи.

## Проверка вручную через curl

```bat
curl -X POST http://127.0.0.1:8000/api/v1/auth/register/ -H "Content-Type: application/json" -d "{\"username\":\"testworker\",\"password\":\"SafePassword-2026-Example!\",\"display_name\":\"Тестовый пользователь\"}"
```

Взять поле `token` из ответа. Для следующего запроса заменить `ВАШ_ТОКЕН`:

```bat
curl http://127.0.0.1:8000/api/v1/shift/ -H "Authorization: Token ВАШ_ТОКЕН"
curl http://127.0.0.1:8000/api/v1/shift/summary/ -H "Authorization: Token ВАШ_ТОКЕН"
```

Команды рассчитаны на Windows cmd. В PowerShell можно использовать `curl.exe`.

## Границы первой версии

- Django и PostgreSQL — реальные, модели/миграции/API/тесты включены в репозиторий.
- Веб-интерфейс работает через Django без переноса файлов; аккаунт и ручная синхронизация доступны в «Ещё» только при ответе локального Django.
- При входе в Django-аккаунт основные экраны друзей, поиска, сообщений и уведомлений используют API. При отсутствии Django или входа остаётся учебный офлайн-прототип. Каталог организаций, отзывы, расширенные настройки конфиденциальности и телефонные контакты пока не интегрированы в серверные экраны.
- Не запускать публичную регистрацию с реальными персональными данными до настройки HTTPS, бэкапов, защиты от спама, юридических документов и обработки персональных данных.
